# 文章收藏整理

目标：让用户快速收藏可读、可检索的生活资料。AI 完成初步整理、关键词和分类，不要求用户逐篇补写或人工修订。整理稿仍是收藏，不自动成为用户认可的知识或亲身经验。

## 先确定存放位置

- **采集目录必须由用户提供。** 从本次消息、当前对话或用户明确维护的配置中寻找已指定的绝对路径；已有有效约定则复用，不重复询问。未提供时直接问：“这次下载的原图、预览图和采集临时文件，放在哪个本地目录？建议选不参与同步的位置。”在得到回答前，不创建采集目录，不下载或落盘采集材料；可继续准备笔记结构。
- 不擅自选择项目 `work/`、`tmp/`、系统临时目录、Downloads 或 Obsidian 附件目录。目录看起来方便或已经存在，不等于用户指定过。目录不可用时说明原因，请其改选；写入权限按环境工具申请。
- 在用户指定的根目录下，以站点和文章 ID 建独立子目录；原图、低清预览、局部裁切、OCR、评论结构和读取检查记录都只放这里。脚本的 `--capture-dir` 是这个已获指定的文章子目录，必须显式传入。
- 采集目录与最终笔记目录分别处理。前者不参与同步；后者按用户已有库和“收藏夹”约定保存。没有最终位置时先生成位于采集目录内的可交付版本，再询问目标位置，不自行假设库路径。
- Obsidian 最终只接收 Markdown 和确实需要的配图。不要嵌入采集日志、识别清单、整批原图、OCR 文件或临时文件路径，不把图片 Base64 写进笔记。不要清理用户整个目录；结束后仅可按用户已有保留规则处理本次临时文件。

## 读取文章、图片和评论

1. 网页访问使用已安装的 `browseros-neo` skill 和 Neo 工具。读当前工具描述，不硬编码旧会话、页面 ID 或工具别名。正文、图片及评论分别覆盖，不拿其中一项猜另外两项。
2. 使用 [references/neo-reading.md](references/neo-reading.md) 完成正文与评论读取；小红书部分包含轮播图片和折叠回复的实测方法。视频帖若观点只在音视频中，需实际读取对应内容；只读描述和封面不能声称总结了视频。
3. **每张图片先阅读，再决定是否入文。** 必须阅读 [references/image-vision.md](references/image-vision.md)：包含图片清单双重核对、逐图完整解码与校验记录、失败补采、本地读取成功路径、缩图参数、局部裁切和 OCR 的边界。下载完成、OCR 成功、视觉模型看到了像素是三种不同状态。
4. 评论视为独立的知识来源。展开全文、子回复、更多回复及分页，滚动正确的评论容器；保留父子关系、作者身份、实践反馈、分歧、纠正、替代品和未回答的问题。不要把购买意向算成实测，不把一个人的说法写成普遍共识。
5. 覆盖检查只保存在本地：预期与实际图片数、逐图视觉读取状态、可见评论数、剩余展开控件、末尾证据和加载失败。数量不符或平台限制时如实报告可见范围，不以“全部完成”掩盖遗漏。影响理解的缺失在最终交付说明中简短注明。

## 整理规则

- **作者观点和评论分开。** 最新约定的“核心摘要”只概括作者；评论紧随其后，置于原文留存之前。核心摘要保持精简；参数或比较确实有助于使用时再加小表格，不为普通生活收藏写论文。
- 图片中的参数、步骤和限定条件纳入整理，并与正文交叉核对。图片显示某部件、表面或标注，不等于证实材质、性能、安全认证或科学因果。
- “疑点与核查”独立记录帖内矛盾、证据不足、待查事项和真正完成的外部核查。没有外查就说明尚未外查；做了外查则附来源和适用范围。不得把 AI 推断塞进忠实摘要、替作者纠错或直接改写原文。
- 评论正文保留关键意见与检索词，不降格为可有可无的补充。闲聊、表情、感谢无需占据主要讨论；有意义的反例和少数意见不能被赞数淹没。
- 选择配图的标准是**删除它是否损失理解**：标注照片、部件位置、操作步骤、姿势、前后或空间对比通常值得保留；装饰封面、重复摆拍、已忠实转写且没有布局意义的纯文字图通常不留。精选数量由内容决定，不固定为两张。图片贴在相关段落旁，附来源图号和简短图注；同一文件不复制多份。
- 提取少量主题与稳定标签，复用库中既有词汇；型号、材料、方法和评论关键词放对应属性或正文。不要把原帖的推广标签全搬入 tags。目录只需粗粒度，不强迫每篇归入唯一精确分类。
- 当前收藏只记录当前来源及其讨论，不静态堆放“你可能还喜欢的旧文章”。动态关联交给 Obsidian 视图或后续对话。
- 不自动改动既有主题知识页。用户另行要求汇总多篇时，把共通方法、不同做法及适用条件合并到宽泛主题笔记的小节，例如《鸡胸肉》中的“做嫩方法”；不要默认每个小问题新建一页。新资料可迭代该节，保留矛盾和用户已有经验。

## Markdown 约定

属性按库的既有命名调整；推荐只用：来源、作者、类型（收藏）、主题、关键词、整理方式（AI 整理），再加少量 tags。已有“待验证”表示尚无实际实践或结果验证，不能拿来表示未读，也不能因为 AI 整理完成就改为已验证。不要冒充用户亲历。

```markdown
# 笔记标题

## 核心摘要
作者的主要观点、做法和适用范围；按需加入必要配图与参数。

## 评论讨论

### 主要观点
实际使用反馈、共识与分歧。

### 关键讨论与回复
保留“谁提问 → 谁回复 → 有何限定或后续”的关系。

### 讨论关键词
值得日后检索的材料、方法、型号和问题。

## 疑点与核查
区分帖内矛盾、待核实与已外部核查，注明证据边界。

## 原文留存

### 作者内容
来源、作者及可保留的原文。

### 评论内容
与作者正文分开，保留关键评论的来源和回复关系。
```

原文留存的目的是真实对照，不能把 AI 重述标成原文。用户提供的正文或有权完整复制的内容，可按请求保留；仅由外部链接获取的受版权保护文章，不默认全文转载，改用来源和允许的短摘录并明确告诉用户范围。不通过附件或采集文件交付绕过该限制。无评论或确实无疑点时简短说明，不虚构内容填充。

## 交付前检查

- 核对数字、单位、型号、否定词、图片顺序及观点归属；图片文字和正文冲突进入疑点区。
- 检查 Markdown 图片引用能在目标库解析，所选附件确实存在，最终包不依赖本机采集绝对路径。附件格式和压缩以可读性为先，小字不能因节省体积变糊。
- 简短报告读取范围、必要的遗漏、保留图片数量和最终文件总大小；不要把采集过程写进知识正文。
- 写入库之前确认已有授权与目标路径；用户已授权则直接完成，不重复请求。仅在当前环境重新验证过的结果才能称为成功，不能由一次读取推断以后都不会失败。
